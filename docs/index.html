Java, uçtan uca depo yönetim sistemi

Open WMS

Mal kabulden adreslemeye, toplamadan sayım ve sevkiyata kadar depo operasyonlarını yöneten, ERP'den bağımsız bir depo yönetim sistemi. Spring Boot backend ve React arayüzü ayrı depolarda; Docker Compose ile tek komutta ayağa kalkıyor.

  • ERP'den bağımsız çekirdek: Mikro ve Uyumsoft entegrasyonları tek bir ErpOrderGateway sözleşmesinin adaptörleri. Yeni bir ERP için bu arayüzü uygulayan bir servis yazmak yetiyor; ERP bağlı değilse sistem yerel veriyle çalışıyor.
  • Benzersiz barkodun yaşam döngüsü Spring Statemachine ile, toplama adresi seçimi Strategy deseniyle yönetiliyor.
  • Hibernate Envers ile denetim kaydı, Spring Security ve JWT ile yetkilendirme, JCache ile önbellek, Liquibase ile şema yönetimi.
  • Entegrasyon testleri Testcontainers üzerinde PostgreSQL 18 ile koşuyor; API sözleşme testleri, arayüzün kullandığı uçların yanıtlarını kayıtlı snapshot'larla karşılaştırıp kırılmaları yakalıyor.
  • Canlı ortam için Actuator ve Prometheus metrikleri, Sentry hata takibi, yapılandırılmış loglar, MinIO dosya deposu, WebSocket bildirimleri ve gömülü Metabase raporları.

Java, olay tabanlı iki servis

rabbit-lab

Backoffice ile e-ticaret vitrini arasında ürün ve stok senkronizasyonu yapan iki Spring Boot servisi. Mesajlaşmanın zor kısımlarını gerçek altyapıyla çözüyor.

  • Transactional outbox: durum değişikliği ve olay aynı transaction'da yazılıyor; relay FOR UPDATE SKIP LOCKED ile birden fazla instance'ta çakışmadan yayınlıyor, publisher confirm'leri paralel bekliyor.
  • At-least-once teslim: tüketici tarafında idempotent işleme ve versiyon kontrolü sayesinde tekrar eden ya da sırası bozulan mesajlar yine doğru sonuç veriyor.
  • Mimari kurallar ArchUnit testleriyle korunuyor; vitrin servisi hexagonal mimariden onion mimarisine adım adım taşındı.
  • Kabul senaryoları Cucumber ile, entegrasyon testleri Testcontainers ile gerçek RabbitMQ ve PostgreSQL'e karşı koşuyor.

public final class InventoryService implements CountStockUseCase {

    @Override
    public void count(CountStockCommand command) {
        transaction.execute(() -> {
            Inventory inventory = inventories
                    .findBySku(command.sku())
                    .orElseThrow(() ->
                        new ProductNotFoundException(command.sku()));

            inventory.count(command.quantity());
            var events = inventory.pullEvents();
            if (events.isEmpty()) return;

            inventories.save(inventory);
            outbox.append(events);  // aynı transaction
        });
    }
}
Java, hexagonal mimari

hexagonal-101

Küçük bir sipariş servisi üzerinden hexagonal mimariyi uygulayan Spring Boot projesi. Her tasarım kararı README'de gerekçesiyle yazılı.

  • Domain JPA'dan ayrı ve değişmez; geçersiz bir sipariş nesnesi oluşturulamıyor, dönüşümü persistence adapter'ı yapıyor.
  • Application katmanı Spring'e bağımlı değil; use case testleri Spring context ve Mockito olmadan koşuyor.
  • Persistable ile kayıt başına atılan gereksiz SELECT kaldırıldı; SQL sayısı testle doğrulanıyor.
  • Her katmanın kendi testi var: domain, use case, @WebMvcTest, @DataJpaTest ve @SpringBootTest. Toplam 33 test.

Hakkımda

Java ve Spring Boot ekosisteminde backend geliştiren bir yazılım mühendisiyim. Domain modelini framework'ten bağımsız tutmayı, servisler arası iletişimi hata durumlarını da düşünerek kurmayı ve davranışı testlerle belgelemeyi önemsiyorum. En kapsamlı işim olan Open WMS'te bir depo yönetim sistemini veri modelinden canlı ortam izlemesine kadar uçtan uca geliştirdim.

Ön yüzde Next.js ve React, TypeScript tarafında NestJS ve Prisma ile de çalışıyorum. Bu sayede bir özelliği veritabanından arayüze kadar tek başıma taşıyabiliyor, ekipte backend ile frontend arasında köprü olabiliyorum.
